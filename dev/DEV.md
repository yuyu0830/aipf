# Dev

AIPF는 Markdown 문서와 Git으로 AI 프로젝트를 이어갈 수 있게 하는 틀이다. 사용자는 준비된 `release`를 clone해서 사용한다. 별도 AIPF 설치나 배포 스크립트 실행은 필요 없다.

## 두 작업의 구분

| 명령 구분 | 대상 | 예시 |
|---|---|---|
| `Dev` | 이 저장소의 개발 환경·메모·개선 이력·Git 운영 | 개발 문서 정리, 배포 방식 변경 |
| `AIPF` | 사용자 프로젝트에 제공할 `template/`의 내용·동작 | 계획 지침 수정, 사용자용 문서 개선 |

구분이 없더라도 문맥이 분명하면 이어서 작업한다. 어느 쪽인지 헷갈리면 반드시 사용자에게 다시 묻는다. Dev에서 AIPF의 프로젝트 운영 절차를 그대로 수행하지 않는다.

## 남겨둘 문서와 기록

- 루트 `AGENTS.md`: 에이전트가 작업 대상을 구분하는 짧은 안내.
- [Requests.md](Requests.md): 새 개선 아이디어와 아직 시작하지 않은 요청. 사용자는 불편한 점과 원하는 결과를 자유롭게 적는다.
- [Status.md](Status.md): 현재 진행 중인 작업의 합의 범위, 진행 위치, 다음 행동. 시작한 요청은 Requests에서 이곳으로 옮겨 중복 관리하지 않는다.
- [History.md](History.md): 완료한 개선의 날짜·결과·이유·관련 커밋. 완료하면 짧게 기록하고 Status에서는 뺀다. main·release 반영 여부는 개발 작업 완료와 구분한다.
- 이 문서: 개발 목적과 Git 운영 참고. Git·배포 작업이나 운영 방식 확인이 필요할 때 읽는다.

평소에는 Requests와 Status만 읽고 갱신한다. 과거 맥락이 필요할 때만 History에서 관련 내용을 검색한다. 완료 기록에는 나중에 재사용할 결론을 남기며 전체 대화나 작업 로그를 복사하지 않는다. 별도 `dev/archive/`는 두지 않는다. 과거 문서 원본은 Git에 보존하며 필요하면 `git show <커밋>:<당시 경로>`로 읽는다.

요청을 적용하기 전에는 이해한 의도, 바꿀 범위, 충분한 결과를 짧게 제안한다. 사용자가 "이 범위로 적용해줘"라고 하면 실행한다. 아이디어에 대한 동의만으로 시작하지 않으며, 이미 범위가 분명한 직접 수정 지시는 별도 승인 단계를 만들지 않는다. 번호 순서대로 처리할 의무는 없다.

혼자 로컬에서 필요한 최소 작업부터 한다. 무결성 검사, 과한 오류 감지, 상시 검증 도구나 일괄 검토 절차는 미리 만들지 않는다. 이후 실제 필요에 맞춰 늘린다.

## Git 사용

이 Git 운영 방식은 이 개발 저장소에 적용한다. 배포할 AIPF의 사용자 프로젝트 운영 규칙과는 별개다.

- 작업은 별도 브랜치에서 이어가며, 작은 수정은 관련 작업과 함께 모아둔다. 파일을 수정할 때마다 또는 대화 한 차례가 끝날 때마다 커밋·push하지 않는다.
- 중요한 체크포인트는 하나의 기능·수정 묶음을 확인해 마무리했을 때, 합의한 구조 변경이 완성됐을 때, 큰 실험 전에 돌아올 기준 상태를 남길 때다. 단순 문구 수정이나 진행 보고만으로 체크포인트를 만들지 않는다.
- 체크포인트에서는 변경 내용을 확인하고 해당 작업을 한 커밋으로 묶어 작업 브랜치에 push한다. 사용자가 명시적으로 커밋·push를 요청하면 그 지시를 따른다.
- 체크포인트 전 수정은 작업 트리에 남겨두어도 된다. 작업을 멈출 때 이어갈 내용이 있으면 `Status.md`에 짧게 적는다. 커밋 빈도를 줄이려고 기존 이력을 합치거나 다시 쓰지는 않는다.

`main`은 Dev와 AIPF 원본을 함께 보관하며, 사용자가 최종 완료를 확인한 뒤 작업 브랜치를 병합한다.

## 배포

`release`는 승인된 main의 `template/`만 루트에 담는 사용자용 브랜치이며 직접 편집하지 않는다.

main 반영 후 에이전트가 아래 Git 명령을 직접 수행한다. 현재 저장소의 기존 로컬 release를 부모로 이어 이전 배포 이력을 보존한다. 별도 배포 스크립트는 두지 않는다.

```bash
git fetch origin
source_commit=$(git rev-parse main)
template_tree=$(git rev-parse "$source_commit:template")
release_commit=$(git commit-tree "$template_tree" -p release -m "release: publish template from $source_commit")
git update-ref refs/heads/release "$release_commit"
git push origin release
```

로컬 release가 origin/release보다 뒤처졌다면 먼저 동기화한다. 분기되거나 충돌하면 상태를 보고하고 해결 방향을 묻는다. 강제 push나 기존 이력 덮어쓰기는 하지 않는다. 개발 문서·자료는 release에 포함하지 않는다.
