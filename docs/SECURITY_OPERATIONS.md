# 보안 및 운영

## 실행 경계

- 기본 파일 쓰기는 프로젝트 루트 내부로 제한한다.
- 명령 실행은 허용 목록을 적용한다.
- 네트워크, 삭제, 외부 전송은 명시적 정책 또는 사용자 승인이 필요하다.
- 경로 정규화 후 symlink 탈출과 `..` 탈출을 차단한다.
- subprocess는 shell 없이 인자 배열로 실행한다.

## 비밀정보

- API 키는 환경 변수 또는 OS secret store에서만 읽는다.
- YAML, `PROJECT.md`, 로그, 모델 프롬프트 기록에 비밀정보를 쓰지 않는다.
- 기록 전 알려진 키와 토큰 패턴을 마스킹한다.
- 외부 모델 전송 전 정책과 데이터 분류를 확인한다.

## 예산과 timeout

task는 시간, 입력 토큰, 출력 토큰, 비용 한도를 갖는다. 한도에 근접하면 handoff를 저장한다. 한도 초과 시 실행을 중단하고 사용자 결정을 요청한다.

## heartbeat

실행 중 에이전트는 주기적으로 session ID, task ID, 시각, 진행률, 최근 checkpoint를 기록한다. timeout 뒤 1회 재시도한다. 두 번째 실패는 사용자 질문으로 바꾼다.

## 감사 가능성

모든 상태 전환, 승인, 명령 결과, 모델 선택, 법정 판결은 audit으로 남긴다. Audit에는 비밀정보가 없는 증거 checksum과 산출물 경로를 기록한다.

## PROJECT.md 투영

`PROJECT.md`에는 목표, 범위, 현재 단계, 진행률, 활성 task, 차단 사항, 최근 결정, 검토 결과, 산출물, 다음 체크포인트, Telegram 전송 조건만 표시한다. 상세 기록은 handoff에 둔다. 사용자는 Telegram 전송 조건만 수정할 수 있다. 오케스트레이터는 해당 값을 보존하고 나머지를 원자적으로 재생성한다.

설치, 승인, 중단 복구, Telegram, 릴리스 검증 명령은 `docs/OPERATIONS.md`를 따른다.
